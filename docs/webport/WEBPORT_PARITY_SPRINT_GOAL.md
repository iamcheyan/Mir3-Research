# webport 行为级 100% 等价冲刺（重写版 goal）— 用户仲裁后的最终标准

## ⚠️ 本文件取代 WEBPORT_PHASE23_GOAL.md 的验收标准

用户原话（不可妥协的合同）：
> "完完全全跟 godot 一样，他有什么功能，我们就有什么功能。它下面的那些按钮都是
> 能点的，我们也要能点。他按住左键能走，我们也要能走，按住右键能跑，我们也要能跑。
> UI 的顶部右上角有哪些图标，它有哪些图标，我们就用哪些图标，整个是要完全一模一样的。"

**验收标准从"像素级截图对比"改为"交互功能 1:1 等价"**：
Godot 客户端能做的每一个操作，网页端必须能用同样的输入方式做到。
不是"看起来像"，是"用起来一样"。

## 一、核心交互等价清单（每条都要真机验证，对照 Godot 实测）

### 输入模型（对照 GameScene.cs 的 Input 处理）
| Godot 行为 | 网页必须 |
|---|---|
| 按住鼠标左键 → 角色走路（跟随指针） | 同：pointerdown+按住 → walk，松开停 |
| 按住鼠标右键 → 角色跑（跟随指针） | 同：右键按住 → run；**必须拦截 contextmenu** |
| 左键点击地面/NPC/怪物 → 走过去+选中/攻击 | 同 |
| 键盘 WASD/方向键移动（若 Godot 有） | 对照源码，Godot 有则必须有 |
| 双击怪物 → 攻击 | 对照 Godot 实测行为 |
| 滚轮 → 缩放/视角（Godot 有的话） | 同 |
| Esc → 关闭当前窗口/打开设置 | 同 |
| 所有 F1-F8、Q/W/E/R、B/V/N、Tab、Enter 快捷键 | 逐个对照 KeyBindManager.cs，一个不漏 |

### HUD 按钮（对照 Godot 界面截图 + ui_tree.json）
- 底部主按钮排：每个图标**必须可点**，点击行为=Godot 同款（打开对应窗口/切页）
- 右上角图标区：Godot 有几个图标就画几个（贴图帧号从 Interface.Zl 取，ui_tree.json
  坐标为唯一权威），每个可点、行为一致
- HP/MP 球、经验条：实时数据绑定 + 点击行为（若有）一致
- 小地图：点击打开大地图等行为一致

### 窗口系统
- 每个窗口的打开/关闭/拖动/置顶/模态行为 = DXWindow 基类同款
- 窗口内每个可交互控件（按钮/滚动条/格子/输入框）都真的能用

## 二、实现纪律（铁律）

1. **禁止"暂未实现"按钮**：任何 Godot 里能点的按钮，网页版点了必须有真实反应
   （打开窗口/发网络包/切换状态）。做不到的网络包就从 Packet.cs + packet_id_dump 补
2. **行为对照以 Godot 源码为最高权威**：Input/GameScene/KeyBindManager 的事件处理
   逻辑逐函数移植；ui_tree.json 提供坐标，行为不猜
3. **真机验收**：每条交互在 Godot 无头客户端（Xvfb 配方）和网页端（CDP）做同样
   操作，录屏/日志对照；已完成的截图对比流程继续保留
4. 服务端零改动；webp23 已提交的战斗/对象系统代码保留继续用（7540a55/0be635d/ee04c68
   不回滚，在此基础上补交互层）

## 三、执行顺序（先把"手感"做对，再铺窗口）

1. **P0 移动手感**：按住左键走/按住右键跑/点击寻路攻击/键盘移动——对照
   GameScene.cs _Input/Process 精确移植（含格步 480ms 节奏、转向、目标格逻辑）
2. **P0 HUD 全量**：底部按钮排+右上角图标区全点亮（可点+行为对），HP/MP/经验条实时
3. **P0 聊天框**：输入可打字（用户已修 DXTextInput）+ Enter 发送 + 频道切换
   + 历史记录上下翻（C.Chat 字段已修）
4. **P1 全窗口**：45+ 窗口逐个点亮（背包/技能/角色/NPC 对话/商店/设置…），
   每个窗口内控件全可交互
5. **P1 键位全表**：KeyBindManager.cs 的绑定逐个移植+验证
6. **P2 边缘**：拖拽物品/叠放/修理/摆摊/行会面板等长尾交互
