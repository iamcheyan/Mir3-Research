# Zircon 任务系统实现调查报告

> 日期：2026-08-12
> 范围：任务如何配置/触发/判定/完成/发奖 + NPC 对话引擎 + 串行任务 + 副线循环任务
> 数据源：`~/development/zircon` 源码（LibraryCore 模型 + ServerLibrary 服务端逻辑）
> 结论先行：**任务系统完全不需要写脚本**——全部是"数据配置"（System.db 里的 QuestInfo/NPCInfo 对象），
> 服务端有现成的判定引擎（击杀计数/物品收集/区域到达），对话引擎支持分支/条件/动作/剧情标记。

---

## 一、任务生命周期（完整闭环）

```
玩家点 NPC → NPCCall(EntryPage) → 对话页 → 按钮[接取] → QuestAccept()
                                                       ↓
        击杀怪物 MonsterObject.Die() → KillMonster 计数 / GainItem 掉落任务物品
        到达区域 Map.GetMovement()   → VisitRegion 计数
        捡起任务物品 PlayerObject.GainItem() → GainItem 计数（够数自动消耗）
                                                       ↓
        所有 Task 完成（UserQuest.IsComplete）→ 回 NPC → 按钮[交任务] → QuestComplete()
                                                       ↓
        校验 → 发奖励（物品/金币/经验/声望/货币）→ Completed=true
```

---

## 二、任务数据结构（System.db 配置对象）

### QuestInfo（任务本体）
| 字段 | 说明 |
|------|------|
| QuestName | 唯一标识（`M3M_EP1_CONVERGE` 这种）|
| QuestType | General / **Daily** / **Weekly** / **Repeatable** / **Story** / Account |
| AcceptText / ProgressText / CompletedText / ArchiveText | 四个阶段的剧情文本 |
| StartNPC / FinishNPC | 接取 NPC / 交任务 NPC（关联 NPCInfo）|
| Requirements | 接取条件列表（QuestRequirement）|
| Rewards | 奖励列表（QuestReward）|
| Tasks | 任务步骤列表（QuestTask）|

### QuestTask（任务步骤）—— 3 种类型
| Task 类型 | 参数 | 判定方式 |
|-----------|------|---------|
| **KillMonster** | MonsterDetails（怪物/地图/Chance 掉率/DropSet/数量）| 杀怪计数 |
| **GainItem** | ItemParameter + MonsterDetails | 任务物品（杀怪掉落，捡起计数）|
| **VisitRegion** | RegionParameter（MapRegion 区域）| 走进区域计数 |

### QuestTaskMonsterDetails（子怪物配置）
- Monster（怪物）+ Map（可空=不限地图）+ **Chance（掉率，1 表示必掉）** + Amount + **DropSet（掉落组位掩码）**

### QuestReward（奖励）
- Item + Amount + **Choice（多选一）** + **Bound（绑定）** + **Duration（限时）** + **Class（职业限定）**

### QuestRequirement（接取条件）—— 串行任务核心
| 类型 | 含义 |
|------|------|
| MinLevel / MaxLevel | 等级范围 |
| **HaveCompleted** | **前置任务已完成（QuestParameter 指向）** |
| HaveNotCompleted / NotAccepted | 前置任务未完成/未接 |
| Class | 职业限定（Warrior/Wizard/Taoist/Assassin 位掩码）|

## 三、服务端判定引擎（关键代码）

### 1. 击杀计数 —— MonsterObject.Die()（~2940 行）
```
对玩家每个未完成任务：
  遍历 task.MonsterDetails：
    怪物匹配 && 地图匹配 && Random(Chance)==0 && DropSet 匹配
    → KillMonster: userTask.Amount += count（封顶 task.Amount）
    → GainItem:    掉落任务物品（Flags=QuestItem，SetTemporary，UserTask 绑定）
```

### 2. 捡起任务物品 —— PlayerObject.GainItem()（~6204 行）
```
捡起物品时：
  匹配 GainItem 任务 && 物品一致 && 非怪物掉落绑定
  → userTask.Amount += count
  → 够数 → 删除物品（SetTemporary+Delete）→ 任务完成
★ 关键：任务物品"收集即消耗"，不需要手动交
★ 怪物掉落的（MonsterDetails>0）由 Die() 处理，普通获取（商店/合成）由 GainItem 处理
```

### 3. 到达区域 —— Map.GetMovement()（Map.cs ~550 行）+ CreateQuestRegions（SEnvir.cs ~945 行）
```
启动时：CreateQuestRegions 把 VisitRegion 任务绑定到地图 Cell
玩家移动进入绑定 Cell：
  → 找到未完成任务 → userTask.Amount = 1 → 推送进度
```

### 4. 完成判定 —— UserQuest.cs
```
UserQuest.IsComplete = 所有 Task 都 Completed
UserQuestTask.Completed = Amount >= Task.Amount
```

### 5. 接取/完成入口 —— PlayerObject.cs
```
QuestAccept(index)    : 校验 QuestCanAccept（前置/等级/职业）→ 创建 UserQuest
QuestCanAccept(quest) : 遍历 Requirements 检查（串行任务在此拦截）
QuestComplete(p)      : 校验 IsComplete → 校验奖励空间 → 发奖励 → Completed=true
```

### 6. Daily/Weekly 重置 —— ProcessQuests()（PlayerObject.cs ~695 行）
```
每 20 秒检查：
  Daily      : 跨天删除已完成任务（可重新接）
  Weekly     : 跨周删除（按 ISO 周）
  Repeatable : 完成即删（可立即重接）
★ 这就是悬赏板/周常 BOSS 的循环机制
```

## 四、NPC 对话引擎（剧情分支核心）

### 对话树结构（NPCInfo）
```
NPCInfo
 ├─ Requirements    （NPC 可见性条件）
 ├─ StartQuests     （可接任务）
 ├─ FinishQuests    （可交任务）
 └─ EntryPage       （入口对话页）
      └─ NPCPage    （一页对话）
           ├─ Say          （对话文本）
           ├─ Checks       （NPCCheck 条件列表——不满足跳 FailPage）
           ├─ Actions      （NPCAction 动作列表——进入页面时执行）
           ├─ Buttons      （NPCButton 按钮→跳转 DestinationPage）
           ├─ SuccessPage  （无文本时自动跳转）
           └─ Values       （NPCValue 动态值显示）
```

### 对话流程（NPCObject.NPCCall 循环）
```
while(true):
  CheckPage(条件) → 失败跳 FailPage
  DoActions(动作) → 执行
  Say 为空 → 跳 SuccessPage 继续
  Say 非空 → 发送对话给客户端，等待按钮
```

### NPCCheck 条件（21+ 种，NPCObject.CheckPage ~410 行）
| 类别 | 检查项 |
|------|--------|
| 基础 | Level / Class / Gold / PKPoints / Horse / Marriage / WeddingRing |
| 物品 | HasItem / CanGainItem / WeaponLevel / WeaponCanRefine / WeaponAddedStats / WeaponElement |
| 任务 | （在 NPC 可见性里，对话页用 DataList）|
| **剧情** | **CheckDataList（标记存在）** / **CheckDataValue（数值比较）** |
| 随机 | **Random（掷骰子）** / RollResult（配合 NPCRoll）|
| 其他 | Currency（货币）/ CheckFame（声望）|

### NPCAction 动作（22+ 种，NPCObject.DoActions ~62 行）
| 类别 | 动作 |
|------|------|
| 物品 | GiveItem / TakeItem / GiveItemExperience |
| 金币 | GiveGold / TakeGold |
| 货币 | GiveCurrency / TakeCurrency |
| **剧情标记** | **AddDataList / RemoveDataList / ClearDataList** |
| **剧情数值** | **ChangeDataValue（累加）/ SetDataValue（设值）** |
| 传送 | Teleport（地图/实例）|
| 其他 | PromoteFame（声望）/ Rebirth（转生）/ Marriage / Divorce / SpecialRefine |

### DataList / DataValue 机制（剧情分支的"记忆"）
```
存储模型: GameNPCData (SEnvir.GameNPCList) — 字段 Category / TypeValue / IntValue1
命名规则: TypeValue = "User_{角色名}" / "Guild_{公会名}" / "Account_{邮箱}"（NPCDataType 作用域）
Category 规则:
  DataList 系列 → "{DataCategory}_NameList"（标记存在 = 记录存在）
  DataValue 系列 → "{DataCategory}"（数值存 IntValue1）

写入（NPCAction）:
  AddDataList     → 不存在则建（布尔开）
  RemoveDataList  → 删除（布尔关）
  ClearDataList   → 清空该类全部
  ChangeDataValue → IntValue1 += 数值（累加）
  SetDataValue    → IntValue1 = 数值（设值）

读取（NPCCheck / 页面显示）:
  CheckDataList   → 记录存在即通过
  CheckDataValue  → IntValue1 与参数比较（缺省 0）
  NPCValue 占位符 → DataList 显示 "True" / DataValue 显示数值（客户端 <ID:默认> 替换）

★ 完全支持"玩家个人剧情状态"——两难抉择、剧情分支、好感度数值都能做
★ 掷骰子: NPCRoll → Random(1,7) 存 NPCVals["ROLLRESULT"] → CheckDataValue.RollResult 判断
```

### NPC 可见性（NPCObject.CanBeSeenBy ~730 行）
```
NPCRequirement: MinLevel / MaxLevel / Accepted / NotAccepted / HaveCompleted / HaveNotCompleted / Class / DaysOfWeek
★ DaysOfWeek：老艄公"周六周日出现"就是靠这个（1<<DayOfWeek 位掩码）
```

## 五、我们的任务设计如何落地

### 串行任务（主线链）
```
任务 B 的 Requirements 加一条 HaveCompleted → QuestParameter = 任务 A
→ 玩家没完成 A 就无法接 B（QuestCanAccept 拦截）
→ 44 个主线任务 = 44 个 QuestInfo，A→B→C 串成链
```

### 对话分支/两难抉择
```
万事通对话页：
  [信船的事] → 按钮 → 页面 A（Say 完整真相）+ AddDataList("SHIP_TRUTH") 
  [半信半疑] → 按钮 → 页面 B（Say 少一半）
后续章节 NPC 用 CheckDataList("SHIP_TRUTH") 分支：
  有标记 → "你知道了船的事……"（剧情 A 线）
  无标记 → "你还不懂船……"（剧情 B 线）
```

### 三值体系（善缘/羁绊/煞气）
```
每个两难选项按钮 → ChangeDataValue("VIRTUE", +2) 等
终章结局页 CheckDataValue("VIRTUE", >=, 8) → 救赎线
★ DataValue 是数值，支持累积和比较
```

### 技能觉醒任务
```
任务步骤: KillMonster 指定怪 ×N（史诗链）→ GainItem 觉醒材料（Chance 5-10%）
完成 → 交 NPC → QuestReward: 技能书（Choice 多选一 / Bound 绑定）
```

### 副线循环（悬赏板/周常）
```
QuestType=Daily / Weekly → ProcessQuests 自动重置
万事通悬赏板 = 一个 NPC，StartQuests 挂多个 Daily 任务
```

### 需要服务端扩展的点（v3 设计超出当前能力）
| 需求 | 现状 | 建议 |
|------|------|------|
| 已学技能检测（HasMagic 检查）| 无 | 服务端加 NPCCheckType.HasMagic + 已学换奖励/精通 |
| 好感度折扣 | 无价格系数 | 用 DataValue 存好感 + 对话页手工折扣逻辑（或扩展）|
| NPC 来信（MailInfo）| 有邮件系统 | 任务完成动作加"发邮件"（NPCActionType.SendMail 扩展）|
| 组队任务人数判定 | 无 | 扩展 NPCCheckType.GroupCount |

### ⚠️ 已知限制（子代理实测发现）
1. **`NPCCheckType.Gender` 枚举存在但服务端未实现**（CheckPage switch 无此分支，直接通过）
2. **`NPCActionType.Message` 枚举存在但服务端未实现**（DoActions switch 无此分支）——发消息要用 `NPCValue` 占位符或对话框文本实现
3. **VisitRegion 只检测一次**（进格即 `Amount = 1`），不可做"停留 N 秒"或"多次到访"
4. **CheckDataList 只有"存在"语义**（无"不存在则通过"的反向操作——需用 FailPage 反向跳转实现）
5. **DataList 改动后 NPC 可见性**需玩家换图/复活才重新判定（NPCRequirement 是视野级缓存）
6. **已完成任务不可重复交付**（QuestComplete 3583 行）——想重复要等 Daily/Weekly 重置

## 六、结论

1. **零脚本**：任务 = System.db 里的数据配置（QuestInfo/NPCInfo），服务端引擎全自动判定
2. **三种步骤够用**：KillMonster / GainItem / VisitRegion + 对话动作 = 能覆盖 95% 主线设计
3. **剧情分支可行**：DataList（布尔标记）+ DataValue（数值）+ NPCCheck/NPCAction = 完整剧情引擎
4. **串行任务原生支持**：HaveCompleted 前置条件
5. **循环任务原生支持**：Daily/Weekly/Repeatable 自动重置
6. **主缺口**：已学技能检测 / 好感度折扣 / 邮件触发 / 组队人数——需少量服务端扩展（都标了扩展点）

> 落地工具：mir2ei 已有 SystemDbProbe --json 导出 + dbviewer 可视化；任务配置可先做 JSON 模板 → 转 System.db（或直接用 Zircon 的编辑器）。
