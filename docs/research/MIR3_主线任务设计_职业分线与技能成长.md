# Mir3 主线任务设计 · 职业分线与技能成长

> 状态：设计中（持续迭代）
> 日期：2026-08-12
> 前置资料：`MIR3_EI_背景故事与世界观资料汇编.md`（世界观/地图/BOSS 分级）

---

## 一、核心设计原则

1. **玩家 40 级毕业**：怪物等级 ≠ 玩家等级，主线等级曲线平缓（序章 1-10 → 终章 38-40）
2. **职业出生点不同 → 前期剧情分线**：战士（比奇）、法师（银杏）、道士（道馆），1-15 级三线并行
3. **中期合流，视角区分**：15 级后共享主线，职业差异靠专属支线 + 同一事件三种"所见"
4. **任务与技能成长强关联**：职业专属任务 = 技能习得/升级的叙事载体（"学会这一招"不是点技能栏，而是完成任务）
5. **主干共享 ~70% + 支线专属 ~20% + 视角差异 ~10%**

## 三、任务能力边界（Zircon 服务端实测，2026-08-12 约定）

> ⚠️ **本章是主线任务设计的硬约束**：所有任务设计必须落在以下能力范围内，
> 超出范围的写法一律不用（或标注为"待服务端扩展"）。依据：`LibraryCore/Enum.cs`、
> `LibraryCore/SystemModels/QuestInfo.cs`、`LibraryCore/SystemModels/NPCInfo.cs` 源码。

### 3.1 ✅ 支持的能力（设计时可自由使用）

**A. 任务步骤（QuestTaskType，共 3 种）**

| 类型 | 说明 | 参数 |
|------|------|------|
| `KillMonster` | 击杀指定怪物计数 | 怪物（可限定地图/掉落组）+ 数量 |
| `GainItem` | 收集任务物品（杀怪掉落自动计数，绑定任务）| 物品 + 数量 |
| `VisitRegion` | 到达指定地图区域 | 区域 + 数量 |

- 任务步骤可多步组合、可顺序推进；全部完成 → 找 NPC 交任务（`FinishQuests`）
- 任务类型（QuestType）：General 普通 / **Daily 每日** / **Weekly 周常** / Repeatable 可重复 / **Story 剧情** / Account
- 接取条件（QuestRequirement）：等级范围 / 是否已接 / 是否已完成 / **职业限定** / 前后置任务链

**B. NPC 对话分支（NPCButton/Page + NPCCheck/NPCAction）——"剧情引擎"**

- **NPCCheck 条件（21 种）**：等级 / 职业 / 性别 / 金币 / 持有物品 / PK 值 / 武器状态（等级/元素/可炼制）/ 坐骑 / 婚姻 / 婚礼戒指 / 空间（背包满?）/ 随机数 / **DataList 标记** / **DataValue 数值** / 声望
- **NPCAction 动作（22 种）**：`Teleport` 传送 / 给收金币 / 给收物品 / `Message` 消息 / **`AddDataList`/`RemoveDataList`/`ClearDataList` 剧情标记** / **`SetDataValue`/`ChangeDataValue` 剧情数值** / 货币 / 声望 / 转生 / 武器炼制 / 婚姻 / 坐骑
- **对话树**：按钮 → 页面多级跳转，Check 条件决定分支走向

**C. 由此可实现的任务设计（我们的主线全部依赖这些）**

| 设计需求 | 实现方式 |
|---------|---------|
| **对话选项分支**（选 A / 选 B 走不同剧情）| ✅ NPCButton 分页 + NPCCheck 条件分支 |
| **剧情选择影响后续**（"是否交出信物"等）| ✅ `AddDataList` 记录选择 → 后续 NPC `CheckDataList` 说不同话 |
| **剧情变量**（章节进度/真相状态）| ✅ DataList / DataValue 标记体系 |
| **递送任务**（A 处取信 → B 处交付）| ✅ `TakeItem` + `GiveItem` + 两个 NPC 组合 |
| **技能觉醒任务**（收集卷轴→交任务→学会）| ✅ GainItem（技能书/觉醒卷轴）+ FinishQuests |
| **职业专属任务**（三线分线）| ✅ QuestRequirement.Class + NPCCheck.Class |
| **每周/每日限时开启**（如神舰开门）| ✅ QuestType.Daily/Weekly + NPCRequirement.DaysOfWeek |
| **双结局/分歧**（封印 vs 救赎）| ✅ DataList 标记 + 终章 NPC 条件分支 |
| **BOSS 战任务**（击杀指定 BOSS）| ✅ KillMonster + `QuestTaskMonsterDetails`（可限定地图/掉率）|
| **声望成长**（万事通声望等级）| ✅ CheckFame / PromoteFame |

**D. NPC 可见性条件（NPCRequirement）**：等级 / 职业 / 任务状态 / **星期几**——NPC 可按天/按任务进度出现（如"神舰开门时失乐园海边出现摆渡人"）。

### 3.2 ❌ 不支持的能力（设计时回避）

| 设计需求 | 现状 | 替代方案 |
|---------|------|---------|
| 护送 NPC / 跟随任务 | 无跟随机制 | ❌ 改"同行到指定点 + 打怪保护"（VisitRegion + KillMonster 模拟）|
| 限时倒计时任务 | 无倒计时压力 | ⚠️ 用 Daily/Weekly 节奏替代 |
| 解谜/机关交互（点开关、按序激活）| 无场景交互触发 | ❌ 改"收集钥匙物品 + 到达区域" |
| 过场动画/剧情演出 | 只有文字对话 | ⚠️ 对话文案 + 网站剧情页补演出感 |
| 声望门槛解锁装备 | 有 CheckFame | ✅ 可做（列为支持）|
| 任务内多选一奖励 | 有（QuestReward.Choice）| ✅ 可做（列为支持）|

### 3.3 设计约定

1. **一切主线设计默认落在 3.1 能力内**；若需 3.2 的能力，先写"待服务端扩展"标记，不阻塞整体设计
2. **剧情分支用 DataList 标记驱动**：每个关键选择定义一个标记名（如 `PANDIAN_CHOICE`、`SHIP_TRUTH`），统一在文档附录登记，避免撞名
3. **NPC 对话树是剧情主要载体**：每章关键 NPC 的对话树（页面/按钮/条件）在设计时画出结构图
4. **技能觉醒任务 = GainItem（技能书）+ FinishQuests（NPC 传授）**，技能书作为任务道具进 System.db

## 五、任务 × 技能成长关联设计（核心创新）

**原则**：技能不是"升级自动学会"，而是通过职业任务习得/觉醒——每个关键技能对应一个叙事节点。
**数据基准**：mir3-website（17173 经典技能表，战士 13 / 法师 26 / 道士 22 = 61 个），
元素四系（火/雷/冰/风）齐全，是玩家熟悉的经典技能，全部纳入任务链。

### 4.0 技能元素体系（法师四系）

### 4.4 设计要点

- **每个关键技能 = 一个"技能觉醒任务"**，任务奖励直接给技能书/觉醒，比打怪掉落更有叙事意义
- **技能叙事与职业母题一致**：战士=守护/传承、法师=四元素觉醒/求知、道士=救赎/超度
- **法师四元素分章觉醒**：序章火/风 → 一-二章冰/雷 → 三章火雷冰 → 四章风秘法 → 五章秘法 → 六章冰雷 → 终章火+禁忌（四系合一）
- **后期技能绑定主线关键角色**：堕落道士、老矿工、牛魔王都成了"传功者"，让角色关系影响成长
- **数据基准**：所有技能名/等级以 mir3-website（17173 经典版）为准；mir2ei 完整表仅作扩展参考（高级元素技能可作为 40 级毕业后的隐藏追求）
- 与现有「魔法技能学习任务」（原版 mission2.htm 三职业）衔接：原版已有"技能学习任务"框架可扩展
