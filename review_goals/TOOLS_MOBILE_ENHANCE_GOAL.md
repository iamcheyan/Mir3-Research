# Mir3 工具集：移动端适配与功能增强总 Goal

- **审查日期**：2026-08-14
- **范围**：`Tools/dbeditor`（8810）、`dbviewer`（8800）、`mapviewer`（8899）、`wilviewer`（8765）、`uieditor`（8820）；按要求跳过 `webclient`。
- **目标**：用户通过手机 + Tailscale 随身开发时，仍能查数据、定位地图、检查资源并安全地回写游戏。
- **运行证据**：Chrome Headless CDP 手机仿真，目标视口 390×844；截图位于 `review_goals/tool_evidence/`。服务均以首页实测；`wilviewer` 原先未运行，按仓库启动命令启动后复测。

### 关键结论

1. **最差**：`mapviewer`、`wilviewer`。两者都以固定桌面工作区为核心；`mapviewer` 还缺 viewport meta，已有移动 CSS 实际无法可靠生效。
2. **次差**：`uieditor`、`dbeditor`。首页工具栏已能挤入手机，但核心编辑面仍是桌面模型，复杂操作会出现溢出或精度问题。
3. **当前最佳**：`dbviewer`，适合作为手机只读查库入口；后续应改善详情表格的卡片化，而不是推倒重做。
4. **基础设施问题**：审查时 8765 初始未监听，工具需要明确健康检查/门户状态；手机用户不应只看到连接拒绝。

## 3. 移动端统一方案：共享 CSS/交互模式，不各自为政

### 3.1 建议架构

建立 `Tools/common/webui/`（或独立静态共享包），各工具只保留领域 CSS 和组件内容：

- `tokens.css`：颜色、间距、层级、`--touch-target:44px`、安全区变量。
- `mobile-shell.css`：`meta viewport`、页面级 overflow、顶部/底部工具栏、抽屉/底 sheet、空态/错误态。
- `data-card.css`：表格→字段卡片、长文本折叠、复制按钮、关联深链。
- `gesture.js`：统一单指平移/双指缩放/拖拽冲突处理；地图、画布仅注入领域回调。
- `portal.js`：健康检查、统一鉴权上下文、最近访问和工具深链。

### 3.2 必须统一的规则

1. 每个入口 HTML 都有 `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`。
2. 390px 作为最低验收宽度；页面级 `scrollWidth <= innerWidth + 1`，允许地图/画布在**内部 viewport**滚动但不允许整页横向溢出。
3. 触控目标最小 44×44px；桌面密集按钮在手机改为抽屉或 bottom sheet。
4. 大数据表格在手机默认字段卡片，提供“原始表格/JSON”二级视图；不能仅用 `overflow-x:auto` 掩盖关键操作。
5. 地图/画布统一：单指平移、双指缩放、双击放大，`touch-action` 明确；页面滚动与工作区手势边界清楚。
6. 键盘可访问性不回归：焦点可见、按钮有 aria-label，移动端外接键盘仍可用。
7. `prefers-reduced-motion` 下关闭动画；网络失败、未启动、空数据和权限拒绝都提供可执行下一步。
8. 视觉回归矩阵至少为 390×844、768×1024、1366×768；每工具保存同名截图与 DOM 几何报告。

### 3.3 鉴权与首页门户

建议增加 `Tools/portal`（或现有服务前置反向代理门户），而不是让每个工具各自实现登录：

- 统一 Tailscale/反向代理鉴权、会话过期和登出；工具服务只接收可信用户上下文。
- 首页列出五个工具、端口、健康状态、数据源时间、只读/可写标识、移动端支持等级。
- 深链参数统一：`?table=NPCInfo&index=294`、`?map=Bichon&x=...&y=...`、`?lib=...&frame=...`。
- dbviewer 默认只读；跳 dbeditor 必须显式动作；同步写库仍遵守停服、备份、双库和 round-trip 纪律。
- 先用轻量门户/共享 CSS，不建议现在做“大一统前端重写”；五个工具的运行时和数据源差异足以证明领域 UI 应保留。

## 4. 实施顺序建议

### Phase 0：可访问与止血（P0，1 周）

1. 建 portal 健康检查；修复 wilviewer 端口未启动时的可见错误（WIL-P0-02）。
2. 五个工具补齐 viewport、页面级 overflow 和触控目标基线；优先 mapviewer（MAP-P0-01）。
3. dbeditor 收口横向溢出与危险同步操作（DBE-P0-01/02）。
4. dbviewer 详情卡片和 dbeditor 深链（DBV-P0-01/02）。
5. uieditor 基础工具栏/底图入口移动化（UIE-P0-01/02），wilviewer 双栏重排（WIL-P0-01）。

### Phase 1：手机可完成核心开发闭环（2–3 周）

- 统一手势与地图触控（MAP-P0-02）；完成 QuestInfo 叠加、测距（MAP-P1-01/02）。
- dbeditor 历史、表间跳转、JSON diff（DBE-P1-01/02/03）。
- wilviewer 帧搜索与动画预览（WIL-P1-01/02）。
- uieditor underlay、画布触控、批量调整（UIE-P1-01/02）。
- dbviewer 虚拟化/增量渲染和地图联动（DBV-P1-01/02）。

### Phase 2：跨工具生产力与协作（3–6 周）

- 多图对比、开发标注（MAP-P1-03/MAP-P2-01）。
- WIL 后台导出打包和 UI 资源语义关联（WIL-P1-03/WIL-P2-01）。
- uieditor 与未来 webclient 的 schema/预览复用（UIE-P1-03）。
- dbeditor 多人冲突保护、dbviewer 开发检查视图（DBE-P2-01/DBV-P2-01）。
- 统一鉴权、审计日志和门户深链完善。

## 5. Top 5 增强与最终建议

### Top 5

1. **MAP-P0-01**：补 viewport + 移动工具栏；这是当前最直接的桌面布局阻断点。
2. **WIL-P0-01**：把图库/帧预览拆成手机工作流；否则移动端资源审计无法闭环。
3. **DBE-P0-02**：消除编辑器字段/排序横溢，避免手机误操作和“看得到但点不到”。
4. **MAP-P1-01**：QuestInfo 任务设计叠加，把地图从查看器变成任务制作工具。
5. **DBE-P1-03 + UIE-P0-02**：JSON diff 与截图 underlay，分别解决数据改动可审计、UI 调整可对照。

### 建议先做什么

**先做 Phase 0 的共享移动壳 + 门户健康检查，再按 `mapviewer → wilviewer → dbeditor → uieditor → dbviewer` 推进。** 这样先消除最差的固定桌面布局与服务不可达问题，再处理写库安全和高价值任务/资源工作流。`dbviewer` 不要与 `dbeditor` 合并：统一入口、元数据和深链即可，保留只读/可写边界更安全。

## 7. 限制与证据说明

- 本次是在线首页 + 手机 CDP 仿真审查，不替代真实 iOS/Android 浏览器和 Tailscale 外网链路测试。
- 核心按钮验证采用 DOM 点击/焦点与滚动可达性；未对每个数据编辑提交真实写库，避免触碰 System.db 写库纪律。
- `wilviewer` 初始端口拒绝连接，随后按仓库命令启动并完成首页复测；这本身记录为服务可用性问题，不判定为前端代码故障。
- mapviewer 源码存在 `@media (max-width:640px)`，但运行首页缺少 viewport meta，故按实际 390px 行为判为 ❌，不能把“存在 CSS 分支”当作已适配。
