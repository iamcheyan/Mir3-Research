## 二、Phase A：P0 修复（先做，不得并行堆新功能）

### A1 下载→阅读状态机
- 用户故事：从书库点击下载或打开后，必须进入正确作品阅读页，不残留书库 modal，URL/hash 与页面状态一致。
- 实现：统一 `selectedBook/bookId` 状态；下载完成后显式 `openReader(bookId)`，保证 `reader-view.active`、hash、缓存内容、标题四者一致；清理旧 modal/reader 状态。
- 验收：冷启动、已有缓存、下载中断后重试三种流程；《こころ》与《羅生門》交替打开不得串书；截图+Playwright/浏览器断言。
- 工作量：S–M。

### A2 搜索排序
- 精确标题 > 标题前缀 > 作者精确 > 子串 > 正文/模糊；结果显示匹配字段。
- 验收：「こころ」精确作品在第一页；「夏目漱石」作者结果排序合理；中日/假名搜索不回归。S。

### A3 建立可验证词典地基
- 不直接假定空壳 JSON 可用；明确数据来源、许可证、体积与构建脚本。先做最小可用按需词典，失败时显示明确状态，不阻塞阅读器。S–M。

## 三、Phase B：学习价值

1. **生词本+复习**（M）：阅读中点词收藏，保存 surface/reading/meaning/source；列表、删除、导出 JSON；后续 SRS。验收离线可用、刷新保留、导入导出 round-trip。
2. **竖排阅读**（M）：按 `docs/vertical-reading-mode-notes.md` 的 vertical-rl MVP，实现桌面/手机切换、进度和返回位置。验收方向、滚动、进度恢复。
3. **阅读统计**（S–M）：阅读分钟、字数、连续天数、目标；隐私本地存储。验收跨刷新/跨作品正确累计。
4. **书签/高亮/笔记**（M）：段落级稳定 ID，不以 DOM 序号为唯一键；导出备份。
5. **JLPT 注音/难度开关**（M）：只在有可靠词表时显示 N5–N1，未知词明确 unknown，不猜级别。

## 四、Phase C：内容与桌面增强

- 本地 `.txt/.epub` 导入：大文件分章，拒绝危险协议；S–M。
- 下载管理：下载进度、暂停/重试/删除单本并释放缓存；S。
- 全文搜索：先抽样评估 IndexedDB 索引体积，再决定；不能首屏加载 11,041 本全文。M–L。
- 平板双页/自动滚屏：≥768px 优先，手机保持单页。S–M。
- 进度/笔记/生词 JSON 导出导入，作为无后端云同步替代。S。
- AI 段落翻译/语法解释：只做 provider 抽象和用户自带 key/本地代理接口；禁止把 key 写入静态资源或 APK。M。

## 五、性能与验收纪律

- 目录数据存在双份约 6–7MB：去重或按需加载前先记录基准；首屏只取分页所需数据。
- 任何大书打开须测 parse、首屏和滚动，不得以“服务返回 200”代替体验验收。
- 必须同时验收 390×844 手机、1280×800 桌面；桌面可用宽屏/双栏，不能把手机单列样式套到桌面。
- 每个阶段：`npm`/项目既有测试、无头浏览器 console 零报错、截图、离线/刷新回归；Android 真机当前未验证。

## 六、实施顺序与出口

Phase A：A1 下载阅读状态机 → A2 搜索排序 → A3 词典地基。
Phase B：生词本 → 竖排 → 统计 → 书签/高亮 → JLPT。
Phase C：本地导入/下载管理 → 导出导入 → 全文索引 → AI 预留。

**第一目标**：A1。现有功能串书/无法进入阅读页会直接破坏信任；修复后再进入学习功能。
